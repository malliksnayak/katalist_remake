# Katalist Remake: Current Project Status & Architecture

This document provides a detailed overview of the current state of the Katalist Remake project, covering the UI flows, backend logic, and the roadmap for upcoming features.

---

## 🚀 1. Core System Overview
Katalist Remake is a tool designed to turn text stories into visual and narrated storyboards. It uses AI to generate scripts, scene descriptions, and high-quality audio narration, all persisted in a local PostgreSQL database.

---

## 🎨 2. UI/UX Flow (Frontend)

The frontend is a modern, single-page application built with **Next.js**, **Tailwind CSS**, and **Shadcn UI**.

### Step 1: Initial Landing & Project Creation
- **Default State**: When you open the app at `/`, you see the "Create Project" view.
- **Story Input**: A large textarea on the left allows users to paste their long-form story or script.
- **Sidebar (Library)**: The left sidebar automatically fetches and displays a list of all saved projects from the database.
- **Project Loading**: Clicking a project in the sidebar updates the URL to `/?id={uuid}`. The app detects this, fetches the full project data (including all scenes), and populates the view.
- **New Project**: Clicking "Create Project" resets the URL and clears the state for a fresh start.

### Step 2: Storyboard Generation
- **Generation Trigger**: Clicking "Generate Storyboard" sends the text to the backend.
- **Real-time Feedback**: A skeleton loader replaces the scene feed while the AI parses the story into distinct scenes.
- **Result**: Upon success, the UI dynamically renders `Scene Cards` representing segments of the story. The URL updates to include the new project ID.

### Step 3: Scene Interaction (Scene Cards)
- **Visuals**: Each card shows a `visualDescription` (intended for image generation) and an `imagePrompt`.
- **Narration**: The `audioScript` is displayed alongside a "Play Audio" button.
- **Smart Playback Logic**:
    1.  **DB Check**: First checks if `scene.audio` exists (fetched initially with the project).
    2.  **Cache Check**: If not in DB, checks the session's browser cache.
    3.  **API Fallback**: If nowhere else, calls the backend to generate audio.
- **Visual Order**: Scenes are strictly ordered from 1 to N using the `sceneOrder` field.

### Step 4: Batch Processing
- **Generate All Assets**: Located in the Top Bar. This triggers a batch process on the backend to generate audio for every scene in the project that doesn't already have it.

### Step 5: Project Management
- **Delete**: Each project in the sidebar has a "Trash" icon. Confirming deletion sends a request to the backend to wipe the project and all associated media from the database.

## ⚙️ 3. Backend Architecture (Spring Boot)

The backend handles the orchestration of AI services and data persistence.

### Data Layer (PostgreSQL & Liquibase)
- **Squashed Schema**: All migrations are consolidated into a single initial schema for clean versioning.
- **Relationships**:
    - `Project` 1 ↔ N `Scene`
    - `Scene` 1 ↔ 1 `Audio`
    - `Scene` 1 ↔ 1 `Image`
- **Cascading**: Deleting a project automatically triggers a deep wipe of all child Scenes, Audios, and Images.

### Service Orchestration
- **ScriptService**:
    - Interfaces with AI to split stories into JSON-formatted scenes.
    - Ensures every word of the original story is captured across the scenes.
    - Persists the new project to the database immediately upon generation.
- **Audio Generation (NarrationOrchestrator)**:
    - Uses the **Kokoro** provider (running locally/externally).
    - **Optimization**: The backend check logic ensures we never regenerate audio if it already exists in the `audios` table unless explicitly "forced."
- **Storage Strategy**: All media (Audio and Images) are stored as **Base64 strings** directly in the database, eliminating the need for complex file system management or external S3 buckets for this local version.

## 🛠️ 4. Ready to Implement (The Roadmap)

While the core flow is solid, the following features are next in line:

### 1. Image Generation (The "Visual" missing link)
- **Current State**: Visuals are just descriptions and prompts.
- **Goal**: Hook up an image generation API (DALL-E, Stable Diffusion, etc.) to actually generate and store the `imageBase64`.

### 2. Export to Revideo
- **Current State**: Button exists but is a placeholder.
- **Goal**: Export the project as a JSON configuration or a rendered video using the Revideo framework.

### 3. Scene Editing
- **Goal**: Allow users to edit the `audioScript` or `visualDescription` of an individual scene and trigger a "Regenerate" for just that specific asset.

### 4. Global Settings
- **Goal**: UI to change the default voice (e.g., swapping `af_bella` for other Kokoro voices) and image style.
